# Спецификация: SEO для Google, ИИ-поиска и Яндекса

Статус: основа реализована, правила действуют для всей дальнейшей разработки. Дата: 2026-11-01.
Решение по реализации: [ADR-0011](../adr/0011-seo-architecture.md). Чек-лист для разработчиков и агентов: [docs/agents/seo-checklist.md](../agents/seo-checklist.md).

## Цели

1. **Google** (приоритет 1): индексация, органический трафик, чистая техническая база.
2. **ИИ-поиск и ассистенты** (приоритет 1): ChatGPT Search, Perplexity, Claude, Gemini, AI Overviews. Нас должны находить, понимать и цитировать.
3. **Яндекс** (приоритет 2).

## Что влияет на видимость в ИИ (и что нет)

ИИ-поиск опирается на обычный веб-индекс и на то, насколько страница понятна как источник фактов. Поэтому почти всё, что полезно для Google, полезно и для ИИ. Конкретно:

| Фактор | Что делаем |
|---|---|
| Страница отдаётся готовым HTML (SSR), не пустой оболочкой | Nuxt SSR, весь контент и разметка в первом ответе |
| Один адрес на один контент, понятная структура | Единые адреса без слеша, один адрес на товар, canonical, хлебные крошки |
| Фактический, уникальный контент | Описания по [content.md](content.md): факты из источника, проверка человеком |
| Структурированные данные | schema.org: Organization, WebSite, BreadcrumbList, CollectionPage, Product |
| Явное разрешение поисковым ИИ-ботам | `robots.txt`, см. ниже |
| Свежесть и достоверность | `lastmod` в sitemap появится вместе с `updated_at` из CMS, выдуманных дат не ставим |
| Авторитетность (упоминания, ссылки, отзывы) | Вне кода: реквизиты, контакты, репутация. Выдуманные отзывы и рейтинги запрещены |

**Чего не стоит ждать.** `llms.txt` Google не использует, и ни один крупный ИИ-поиск публично не подтвердил, что читает его. Файл дешёвый, мы его ведём, но на него не рассчитываем. Главное для ИИ остаётся обычным: хороший контент, доступный HTML, разметка, доступ для ботов.

### Политика для ИИ-ботов

Боты делятся на три типа. Названия взяты из публичных справочников, **перед запуском сверить с документацией вендоров**.

| Тип | Боты | Влияет на | Решение |
|---|---|---|---|
| Поисковые | OAI-SearchBot, Claude-SearchBot, PerplexityBot | Попадание в ответы ИИ-поиска | **Разрешены явно** |
| По запросу пользователя | ChatGPT-User, Claude-User, Perplexity-User | Чтение страницы, когда её просит человек | **Разрешены явно** (часть вендоров может не учитывать robots.txt) |
| Обучающие | GPTBot, ClaudeBot, Google-Extended, CCBot, Applebot-Extended, Meta-ExternalAgent | Использование контента для обучения моделей. На поисковую выдачу не влияют | **Решение заказчика**, сейчас разрешены |

Переключатель: `runtimeConfig.aiTrainingCrawlers` в `nuxt.config.ts` (`allow` или `disallow`). Запрет обучающих ботов необратим в одну сторону (уже собранное не вернуть), а разрешение может повысить шанс, что модели «знают» бренд. Это бизнес-решение, оно вынесено в открытые вопросы.

## Как это устроено в коде

Единые точки правды, чтобы SEO не расходилось:

| Что | Где |
|---|---|
| SEO страницы (title, description, canonical, Open Graph, robots, JSON-LD) | `usePageSeo()` в [usePageSeo.ts](../../apps/web/app/composables/usePageSeo.ts). Единственный способ задать SEO |
| Реестр страниц: что индексируется, что закрыто и почему | [app/seo/entries.ts](../../apps/web/app/seo/entries.ts) |
| Генерация `sitemap.xml`, `robots.txt`, `llms.txt` | серверные маршруты в `apps/web/server/routes/`, логика в `app/seo/` |
| Разметка schema.org | [structured-data.ts](../../apps/web/app/utils/structured-data.ts) |
| Единые правила адресов, описаний, заголовков | [utils/seo.ts](../../apps/web/app/utils/seo.ts) |
| Проверка собранного сайта | [scripts/seo-audit.mjs](../../scripts/seo-audit.mjs), запускается в CI |

### Как поддерживается консистентность

1. **Тесты** (`tests/unit/seo-*.test.ts`): каждая страница вызывает `usePageSeo`, каждая статическая страница есть в реестре и наоборот, в страницах нет прямых `useSeoMeta` и `useHead`, разметка не содержит выдуманных данных.
2. **Аудит итогового HTML** (`pnpm seo:audit`) после `pnpm generate`. Ошибка роняет CI и блокирует деплой. Проверяет:
   - `<html lang="ru">`, один `<title>`, один `description`, один `h1`, один `meta viewport`;
   - canonical: один, абсолютный, совпадает с адресом страницы; `og:url` равен canonical;
   - Open Graph и Twitter Card, `og:image` абсолютный и существует в сборке;
   - дубли `title` и `description` между индексируемыми страницами;
   - JSON-LD разбирается, есть `@context` и `@type`; на главной Organization и WebSite; на страницах каталога BreadcrumbList с правильной последней позицией; на товаре ровно один Product без `offers` без цены и без выдуманных отзывов и рейтинга;
   - `img` с `alt`, битые внутренние ссылки, `target=_blank` без `rel=noopener`;
   - sitemap: нет дублей, нет закрытых страниц, есть все индексируемые, есть обязательные страницы, все адреса существуют; `robots.txt` со ссылкой на sitemap и без общего запрета; `llms.txt` ссылается только на страницы из sitemap;
   - страница 404 закрыта от индексации и без canonical.
   Аудит проверен «мутационно»: на собранном сайте искусственно вносились 17 поломок, и он поймал каждую.
3. **Безопасное значение по умолчанию**: всё, что не объявило SEO через `usePageSeo` (оболочки `404.html` и `200.html`, новая страница без вызова), закрыто `noindex`. Открыть страницу может только `usePageSeo`.
4. **Режимы сборки**: `production` (открыт) и `demo` (закрыт, GitHub Pages). CI собирает и проверяет оба.

## Правила адресов

- Только `https`, один домен (`agroed.by`, **не куплен**, адрес предварительный). Вариант с `www` или без выбираем при запуске и настраиваем 301-редирект на основной.
- Адреса **без завершающего слеша** (кроме главной), строчными латинскими буквами через дефис. На сервере слеш на конце редиректится 301 на адрес без него (настроить при деплое).
- Один адрес на один контент: товар открывается только по адресу своей категории `/catalog/<категория>/<товар>`, остальные варианты дают 404.
- Параметры (`utm_*`, `gclid`, `yclid`, `fbclid`) контент не меняют. Для Яндекса в `robots.txt` задан `Clean-param`, для Google работает canonical на адрес без параметров.

## Правила для типов страниц

| Страница | `title` | `description` | `h1` | Разметка |
|---|---|---|---|---|
| Главная | основная формулировка бренда | кто мы, что продаём, для кого | один, на странице | Organization, WebSite |
| Каталог | «Каталог техники и оборудования…» | что в каталоге | «Каталог» | BreadcrumbList, CollectionPage |
| Категория | «{Категория} в Беларуси: каталог» | описание категории + как заказать | название категории | BreadcrumbList, CollectionPage |
| Товар | «{Название}, цена по запросу» | **начинается с названия товара**, затем суть, цена по запросу | название товара | BreadcrumbList, Product |
| Информационные страницы | по смыслу страницы | 1–2 предложения по сути | один | при необходимости FAQPage, LocalBusiness |
| Корзина, ошибки | любой | любое | один | нет, `noindex` |

Требования: `title` до 70 символов (после суффикса « | АгроЭд»), `description` 50–170 символов, оба уникальны. Шаблоны заголовков **временные**: их нужно перепроверить по семантическому ядру (ключевым запросам), которого пока нет, см. открытые вопросы.

## Что открыто и что закрыто от индексации

| Страница | Индексация | Причина |
|---|---|---|
| `/`, `/catalog`, категории, товары, `/privacy`, `/consent` | открыта | в sitemap |
| `/about`, `/delivery`, `/contacts` | **закрыта**, пока заглушки | страницы без содержимого вредят оценке сайта. Откройте в реестре, когда появится текст |
| `/cart` | закрыта | личная страница, нет ценности для поиска |
| 404, страницы ошибок | закрыты, без canonical | |
| Демо (GitHub Pages) | закрыто целиком | не конкурировать с боевым доменом. `robots.txt` на Pages лежит не в корне домена и роботами не читается, поэтому защита идёт через мета-тег `noindex` на каждой странице |

## Фильтры, сортировка, пагинация (правила на будущее)

Фильтры появятся в категориях. Заранее фиксируем, чтобы не плодить дубли:

- Адреса с фильтрами и сортировкой (`?brand=…&sort=…`) **не индексируются**: canonical ведёт на категорию без параметров, метка `noindex, follow`, в sitemap не попадают.
- Исключение: отдельные **посадочные страницы** под частые запросы (например, «тракторы МТЗ») с чистым адресом, уникальным заголовком и текстом. Создаются осознанно, добавляются в реестр и sitemap.
- Пагинация: у каждой страницы свой canonical (на себя), в sitemap только первая страница категории, остальные доступны по ссылкам. Без `rel=prev/next` (его не используют).
- Для Яндекса незначащие параметры закрываем `Clean-param`, а запрет обхода через `Disallow` не используем там, где нужен `Clean-param` (при совпадении приоритет у `Disallow`).

## Яндекс

- Регион сайта (Беларусь) и подтверждение прав задаём в Яндекс Вебмастере при запуске, вместе с Search Console (см. [analytics.md](analytics.md)).
- `Clean-param` для меток отслеживания уже в `robots.txt`.
- Файл `robots.txt` без устаревших директив (`Host` не используется).

## Что остаётся сделать

Сделано в основе: usePageSeo, реестр, sitemap, robots, llms.txt, Open Graph, schema.org, аудит в CI. Дальше:

1. **Семантическое ядро**: список реальных запросов покупателей по категориям. Без него заголовки и описания остаются временными шаблонами. Нужно от заказчика или SEO-специалиста.
2. **Содержимое**: реальные тексты страниц, описания товаров, фото с `alt` (см. [content.md](content.md)). Разметка не заменяет контент.
3. **Реальные данные организации** в `company.ts`: тогда Organization получит юридическое название, УНП, адрес, телефон. Затем LocalBusiness со страницей контактов.
4. **FAQPage** после появления страницы FAQ. Расширенные сниппеты Google для FAQ сейчас доступны ограниченному кругу сайтов, но структурированные вопросы и ответы полезны для ИИ.
5. **Реальные фото** товаров: `image` в Product, `alt`, адаптивные размеры, форматы AVIF/WebP.
6. **`lastmod` в sitemap** из `updated_at` CMS.
7. **Скорость** (Core Web Vitals): измерить Lighthouse на боевом сервере, настроить кэш и сжатие, `Cache-Control` для статики, HTTP/2 и HTTP/3.
8. **Серверные настройки** при деплое: HTTPS, редиректы (`http→https`, `www`, слеш на конце), заголовки безопасности, `X-Robots-Tag` для закрытых окружений.
9. **Search Console, Яндекс Вебмастер, Bing Webmaster**: перед запуском.
10. **Проверка разметки** в Rich Results Test и Schema Markup Validator после выхода на боевой домен.
