# ADR-0012: Сквозные тесты на Playwright

- Статус: Принято
- Дата: 2026-11-01

## Контекст

Модульные тесты проверяют логику, но не то, что видит посетитель: гидратацию, работу формы в браузере, маску телефона с курсором, сохранение корзины, раскладку на телефоне. Эти поломки находились только ручным прогоном. Для заявки (главная пользовательская функция сайта) нужна автоматическая защита.

## Решение

- **Playwright** (`@playwright/test`) в `apps/web`, тесты в `apps/web/e2e/`.
- Тесты идут против **статической сборки** (`pnpm generate`), которую раздаёт маленький сервер `e2e/static-server.mjs`, то есть против того, что получит посетитель. Зависимостей, кроме Playwright, нет.
- Два проекта: **desktop** (1280×800) и **mobile** (390×844 с касаниями). Все сценарии, кроме специфичных для одного размера, идут в обоих.
- Включены классические скроллбары (как в Windows), иначе тест на смещение раскладки между страницами с прокруткой и без ничего не проверяет.
- Каждый тест автоматически падает при **ошибках и предупреждениях в консоли браузера** (так находятся ошибки гидратации и ошибочные ресурсы). Ожидаемые сообщения, например запись о 404, разрешаются явно в самом тесте.
- Страница отдаёт метку `data-hydrated` после гидратации, тесты ждут её перед действиями, иначе клик по серверному HTML ничего не делает и тест нестабилен. Метка появляется только в браузере и на SEO не влияет.
- В **CI** тесты идут после SEO-аудита на той же боевой сборке (до демо-сборки), с одним повтором при падении; при ошибке сохраняется отчёт с трассировкой и скриншотами.

## Что покрыто

Корзина (добавление с количеством с карточки и страницы товара, суммирование, сохранение, синхронизация вкладок, изменение количества, удаление, испорченное хранилище, недоступные товары, 404 на чужой адрес), форма заявки (проверка полей, организация и УНП, согласие, блокировка отправки, ловушка для ботов, успешная отправка), телефон (префикс, маска, Backspace, вставка в любом виде, правка в середине), раскладка (горизонтальный скролл, смещение при скролле, мобильное меню).

## Запуск

```bash
pnpm generate                          # собрать сайт
pnpm exec playwright install chromium  # один раз, либо E2E_BROWSER_CHANNEL=msedge с установленным Edge
pnpm test:e2e
```

Локально на Windows перед повторной сборкой удалить `apps/web/node_modules/.cache` и `apps/web/.output`.

## Последствия

- Сборка нужна перед тестами, поэтому они медленнее модульных (около минуты на оба размера).
- Тесты завязаны на русские подписи и роли: правка текста кнопки требует правки теста. Это осознанно: подписи часть продукта и доступности.
- Когда появится серверная часть заявок (`orderMode: api`), добавятся тесты с реальным приёмом заявки на тестовой базе.
- Сквозные тесты доступности (axe) пока не добавлены, это кандидат на следующий шаг.
