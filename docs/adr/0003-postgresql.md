# ADR-0003: PostgreSQL как БД

- Статус: Принято
- Дата: 2026-10-27, подтверждено 2026-11-01

## Контекст

Данные: дерево категорий, 500–3000 товаров, фото, разные характеристики по категориям, заказы. Нужны фильтры по характеристикам.

## Варианты

1. **PostgreSQL.** Деревья (рекурсивные запросы), JSONB для гибких атрибутов с индексацией, полнотекстовый поиск, зрелый, поддерживается всеми рассматриваемыми CMS.
2. MySQL/MariaDB. Подходит, но JSON-возможности слабее.
3. SQLite. Просто на старте, но хуже для продакшена с админкой и несколькими пользователями.

## Решение

PostgreSQL **17** (поддерживается до 2029 года), образ `postgres:17-alpine`, закреплён мажорной версией. Выбрана 17, а не более новая, потому что она лучше всего протестирована со всеми кандидатами на роль CMS.

Параметры, заданные при создании базы: кодировка UTF-8, провайдер локали ICU с локалью `ru-RU` (русская сортировка), часовой пояс `Europe/Minsk`. Это нельзя изменить после создания без пересоздания базы, поэтому зафиксировано сразу.

## Проверка

Выполнена 2026-11-01 на локальном Docker: запуск, кодировка и сортировка, сохранность при перезапуске, резервная копия и восстановление, доступ только с локального адреса. Подробности: [infrastructure.md](../specs/infrastructure.md).

## Последствия

- Локальная разработка и продакшен через Docker.
- Резервные копии `pg_dump -Fc`, на продакшене по расписанию и с копией вне сервера.
- Обновление на новую мажорную версию PostgreSQL выполняется через дамп и восстановление.
- Модель характеристик товаров (JSONB или EAV) решается отдельно, [ADR-0004](0004-product-attributes-model.md).
