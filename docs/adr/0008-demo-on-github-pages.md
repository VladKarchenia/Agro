# ADR-0008: Демо-сайт на GitHub Pages

- Статус: Принято
- Дата: 2026-10-27

## Контекст

Заказчику и команде нужен адрес, по которому можно смотреть актуальную версию сайта до появления боевого сервера. GitHub Pages раздаёт только статику.

## Решение

Демо публикуется на GitHub Pages через GitHub Actions (`.github/workflows/ci.yml`) при каждом push в `main`, после прохождения линтера, проверки типов и тестов.

- Сборка: `nuxt generate` с пресетом `github_pages` и `NUXT_APP_BASE_URL=/<имя репозитория>/`.
- Данные в демо моковые (`apps/web/app/data`), реальный каталог и CMS не подключаются.
- Демо **закрыто от индексации** (`<meta name="robots" content="noindex, nofollow">`, включается переменной `NUXT_PUBLIC_SITE_ENV=demo`), чтобы не создавать дубль боевого сайта в Google и Яндексе.
- Боевая версия работает как SSR на VPS (ADR-0005). Pages служит только витриной для просмотра.

## Последствия

- Репозиторий должен быть публичным (на бесплатном тарифе GitHub Pages для приватных репозиториев недоступен). В репозитории не должно быть секретов и закрытых данных.
- В настройках репозитория нужно один раз выбрать: Settings → Pages → Source: **GitHub Actions**.
- Динамика (корзина, заявки, CMS) в статическом демо работать не будет, пока не появится отдельный бэкенд для демо.
- Адрес демо: `https://<логин>.github.io/<репозиторий>/`.
- На Windows повторный `nuxt generate` может падать с `EPERM: operation not permitted, rename` в `apps/web/node_modules/.cache` (Nitro пишет кэш пререндера атомарным переименованием). Перед локальной сборкой удалить `apps/web/node_modules/.cache` и `apps/web/.output`. В CI кэш всегда чистый, там проблемы нет.
- На Windows в Git Bash переменную `NUXT_APP_BASE_URL=/Agro/` нужно задавать с `MSYS_NO_PATHCONV=1`, иначе Git Bash подменяет путь на `C:/Program Files/Git/Agro/`.
