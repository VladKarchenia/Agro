# ADR-0001: Nuxt для витрины

- Статус: Принято
- Дата: 2026-10-27

## Контекст

Главная цель сайта: поисковая выдача (Google, ИИ-поиск, Яндекс). Нужны серверный рендеринг, полный HTML на первый запрос, управление мета-тегами, sitemap, schema.org. Команда: Frontend Lead с опытом во фронтенде, предпочтение Nuxt.

## Варианты

1. **Nuxt (Vue, SSR/гибридный рендеринг).** Нативный SSR, `routeRules` для кэширования (SWR/ISR) и статики по маршрутам, зрелые SEO-модули, Nitro даёт серверные эндпоинты на Node.
2. Next.js. Аналогичные возможности, но не совпадает со стеком и предпочтениями команды.
3. Чистый SPA. Не подходит по SEO.

## Решение

Nuxt с SSR и кэшированием через `routeRules`. Стили: Tailwind. UI-компоненты: кастомные по брендбуку, при необходимости отдельные headless-библиотеки.
Конкретная версия Nuxt, менеджер пакетов (предположительно pnpm) и модули фиксируются при создании скорлупы.

## Последствия

- Для каталога на 500–3000 страниц достаточно SSR с кэшем, полная предгенерация не обязательна.
- Серверные эндпоинты Nitro можно использовать для приёма заявок и уведомлений, отдельный Node-сервис пока не нужен.
